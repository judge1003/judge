# Judge 홈서버 앱 모음

안드로이드 앱 2개와 미니PC 모니터링 구성을 담은 저장소입니다.

| 모듈 | 구성 | 설명 |
|---|---|---|
| `app/` | 안드로이드 앱 | **세탁실 대시보드** — NAS 대시보드 전용 앱 (5분 백그라운드 동기화 + 수동 새로고침) |
| `hub/` | 안드로이드 앱 | **통합관리 시스템** — 포토/파일 스테이션, 자동 백업, 대시보드 (자체 서버 연동) |
| `server/` | Node.js (Docker) | 미니PC에 올리는 자체 API 서버 — 파일/사진/백업 처리 |
| `monitoring/` | PowerShell 등 | 미니PC 감시 스크립트 (CPU/MEM/디스크/로그인 알람) + Uptime Kuma |

## 통합관리 시스템 (hub) — Nextcloud/Immich 없이 자체 구현

윈도우 탐색기 느낌의 블랙 테마 (설정에서 블랙/다크블루/라이트 변경 가능).

- **파일 스테이션** — 서버 폴더 탐색(주소창+수정날짜/크기 열), 업로드(＋버튼), 길게 눌러 삭제.
  파일을 누르면 폰의 편집 앱으로 열리고, **수정 후 돌아오면 자동으로 서버에 재업로드**됩니다.
- **포토 스테이션** — 백업된 사진을 최신순 격자로 표시(썸네일은 서버가 생성), 눌러서 크게 보기, 길게 눌러 원본 다운로드.
- **자동 백업** — 설정에서 켜면 **와이파이 + 충전 중일 때만** 새 사진을 서버로 올립니다. "지금 백업 실행" 버튼도 있습니다.
- **대시보드** — 모니터링(Netdata 등) 웹 화면.
- **설정** — 서버 주소/토큰(저장 시 연결 테스트), 백업 on/off, 색상 테마.

### AI 사진 검색 (선택)

Gemini API 키를 넣으면 서버가 백업된 사진에 한국어 태그(바다, 강아지, 음식…)를
자동으로 붙이고, 포토 스테이션의 🔍 검색창에서 태그로 검색할 수 있습니다.

1. https://aistudio.google.com 에서 무료 API 키 발급
2. `server/.env`에 한 줄 추가: `GEMINI_API_KEY=발급받은키`
3. `docker compose up -d` 로 재시작 → 10분 주기로 새 사진을 자동 분석

- **기존 사진은 보내지 않습니다**: 첫 실행 시점에 이미 서버에 있던 사진(대용량 보관분)은
  자동으로 제외 등록되고, **이후 새로 백업되는 사진만** 태깅됩니다.
  기존 사진까지 전부 태깅하려면 `.env`에 `AI_TAG_EXISTING=true` 추가 (대용량이면 비추천)
- 무료 한도 보호를 위해 주기당 30장씩 분석합니다 (`AI_BATCH`로 조절)
- 키를 넣지 않으면 AI 기능은 꺼진 채로 동작하며, 사진은 어디에도 전송되지 않습니다
- **참고**: 이 기능을 켜면 신규 사진(축소본)이 분석을 위해 Google 서버로 전송됩니다

### 자체 서버 (server/) 설치 — 미니PC(윈도우+Docker)

1. `server/` 폴더를 미니PC로 복사 (예: `C:\HomeServer\server`)
2. 같은 폴더에 `.env` 파일 생성: `API_TOKEN=원하는비밀값`
3. `docker-compose.yml`의 volumes 왼쪽 경로를 실제 저장 위치로 수정
4. `docker compose up -d`
5. 허브 앱 설정에 서버 주소(`http://미니PC IP:8585`)와 같은 토큰 입력

## 세탁실 대시보드 (app)

NAS 대시보드(`http://judge.dscloud.me:3033/Dashboard/laundry/`)를 보는 전용 앱입니다.

## 기능 (세탁실 대시보드)

- **대시보드 표시** — 앱을 열면 NAS의 세탁실 대시보드를 바로 보여줍니다.
- **수동 새로고침** — 상단 툴바의 새로고침 버튼 또는 화면을 아래로 당기기(pull-to-refresh)로 언제든 즉시 갱신할 수 있습니다.
- **자동 새로고침** — 다른 앱을 보다가 돌아오면(30초 이상 경과 시) 자동으로 최신 데이터를 다시 불러옵니다. 열 때마다 항상 최신 상태입니다.
- **5분 간격 백그라운드 동기화** — 앱을 실행하지 않아도 WorkManager가 약 5분 간격으로 대시보드 데이터를 받아 기기에 캐시합니다.
- **오프라인 캐시** — NAS에 연결할 수 없을 때는 마지막으로 캐시된 데이터를 캐시 시각과 함께 보여줍니다.
- 상단 툴바에 **마지막 업데이트 시각**이 항상 표시됩니다.

## APK 다운로드 방법

1. GitHub 저장소의 **Actions** 탭 → 최신 **Build APK** 실행 → `laundry-dashboard-apk`(세탁실) / `minipc-hub-apk`(통합관리) 아티팩트 다운로드
2. `main` 브랜치에 머지되면 **Releases**의 `latest` 릴리스에서 휴대폰으로 바로 두 APK를 받을 수 있습니다.
3. 휴대폰에서 APK 설치 시 "출처를 알 수 없는 앱" 설치 허용이 필요합니다.

## 빌드 방법 (로컬)

Android Studio에서 프로젝트를 열거나:

```bash
gradle :app:assembleDebug   # 세탁실 대시보드 → app/build/outputs/apk/debug/app-debug.apk
gradle :hub:assembleDebug   # 통합관리 시스템 → hub/build/outputs/apk/debug/hub-debug.apk
```

## 알아두면 좋은 점 (5분 간격 관련)

- Android의 `PeriodicWorkRequest`는 최소 주기가 15분이라, 이 앱은 작업이 끝날 때마다 5분 뒤 작업을 다시 예약하는 방식으로 5분 간격을 구현했습니다.
- 다만 Android의 배터리 절전(Doze) 모드에서는 시스템이 백그라운드 실행을 늦출 수 있어 **항상 정확히 5분은 보장되지 않습니다.** 화면을 켜고 앱을 열면 즉시 최신 데이터를 새로 불러오므로 실사용 체감에는 문제가 없습니다.
- 배터리 최적화 예외(설정 → 배터리 → 배터리 사용량 최적화 제외)에 이 앱을 추가하면 백그라운드 주기가 더 정확해집니다.
- 근본적인 지연은 NAS 서버 쪽 데이터 수집 주기(5분)에 달려 있습니다. 서버가 5분마다 데이터를 만든다면, 앱이 아무리 자주 가져와도 서버 데이터 이상으로 최신일 수는 없습니다.
